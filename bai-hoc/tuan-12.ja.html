ロードマップのルール: 模試で2回連続80%以上（timedモード、資料を見ない）を取ったら、「もう少し復習してから」と待たずにすぐ予約します。Tutorials Dojoの模試は本番より少し難しいため、TDの80%はおおむね本番の750〜800点に相当します（コミュニティの経験からの推定で、公式の数値ではありません）。早めに予約すると、学習を続ける強制力にもなります。試験日が決まれば先延ばしする理由がなくなります。

AWS Certificationアカウント
  • aws.training/certification → Sign inを開きます。Amazon account、Builder ID、または企業アカウントでログインできます。初回はCertMetrics（AWSの認定管理システム）に移動し、プロフィールを入力します。
  • プロフィールの氏名は、試験に持参する身分証と完全に一致させてください。姓名の順序、アクセント記号、ミドルネームまで合わせます。日本で在留カードやベトナムのpassportを使って受験するなら、アクセント記号なしで、passportの順序どおりに入力します（例: HO VAN QUYならFirst nameはVAN QUY、Last nameはHO、またはpassportでの区切り方に従う）。氏名が違うと入室を拒否され、受験料も失います。予約後の氏名修正はsupport経由になります。
  • まもなく変わる会社のメールではなく、個人のメールを使います。認定、badge、voucherは3年間このアカウントに紐づきます。
  • すでに他のAWS認定（例: Cloud Practitioner）を持っているなら、Benefitsで次回試験用の50% off voucherを取得し、Pearson VUEの支払い時にコードを適用します。voucherには有効期限があるので確認してください。
accommodation「ESL +30 minutes」の申請（予約前に必ず行う）
英語で受験し、英語が母語でない場合は30分の延長を申請できます。このaccommodationは予約前に承認されている必要があります。予約後に申請しても既存の予約には適用されず、キャンセルして予約し直すことになります。日本語で受験する場合はESLを申請できません（ESLは英語の試験のみ）。
  1. CertMetricsでメニューRequest Exam Accommodationsを開きます（メニュー名は多少異なる場合があるので、実際の画面で要確認）。
  2. accommodation ESL +30 MINUTESを選びます。証明書類は不要で、通常は自動承認か数営業日で承認されます。
  3. ステータスがApprovedになるまで待ちます。そうなってから初めてPearson VUEでScheduleを押します。予約時の試験時間は130分ではなく160分と表示されます。

その他のaccommodation（医療上の理由による時間延長、個室、screen reader）は書類が必要で承認にも時間がかかるため、このロードマップでは扱いません。

確認クイズ

3. アプリケーションがSQSに400 KBのmessageを送るとエラーになります。least operational overheadでの修正方法は？

SQS Extended Client Libraryを使ってpayloadをS3に保存し、SQSにはpointerだけを載せます。従来の上限は256 KBです（AWSは2025年に1 MBへ引き上げました、要確認。ただし試験では古い数値で問われる可能性があります）。よくある誤答: Kinesisへの移行（recordは1 MBまで扱えますが、アーキテクチャ全体の変更になりleast overheadではない）や、messageを手作業で分割すること。

4. objectを10日後にS3 StandardからStandard-IAへ、20日後にGlacier Deep Archiveへ移すlifecycle ruleを作ると、Consoleがエラーを出します。なぜですか。

StandardからStandard-IAへの移行はobject作成から最低30日が必要なので、「10日」は無効です。さらに、IAに入ったobjectは次のGlacierへ移る前に少なくとも30日そこに置く必要があります（20日目の移行は、IAに入ってから10日しか経っていない）。修正: IAは30日目、Deep Archiveは60日目以降。ひっかけ: Glacier Deep Archiveのmin duration 180日は課金の話で、lifecycleの条件ではありません。

5. Aurora MySQLを別RegionへDRし、RPOは5秒未満、RTOは1分未満が必要です。何を選びますか。

Aurora Global Database。RPOは約1秒、secondaryをpromoteしたときのRTOは1分未満です。よくある誤答: RDSのcross-Region read replica（lagが数分になることがあり、promoteも遅い）や、snapshotのcross-Region copy（RPOが数時間）。DynamoDB Global TablesはDynamoDB用で、Aurora用ではありません。

6. DynamoDBのtableで毎秒100回のstrongly consistent readが必要で、各itemは6 KBです。RCUはいくつ必要ですか。

200 RCU。6 KBのitemは4 KB単位で2つに切り上げ、strongly consistentでは1単位あたり1 RCU → 1 readあたり2 RCU、毎秒100 readを掛けて200。eventually consistentならその半分の100です。ひっかけ: 切り上げを忘れること（6/4 = 1.5で、1ではない）。

7. 設問に"an application needs a static IP address that clients can whitelist; traffic is UDP; users are worldwide"とあります。何を選びますか。

Global Accelerator。static IPとUDPの2つのキーワードが同時にあるので、CloudFront（HTTPのみ、static IPなし）とALB（static IPなし、HTTPのみ）は外れます。NLBはstatic IPを持てますが1 Region内だけで、worldwideには最適ではありません。

8. 設問に"determine who modified the security group rule last week"とあります。CloudTrailとConfigのどちらを選びますか。

CloudTrailは「誰が、いつ、どのAPIを呼んだか」に答えます（AuthorizeSecurityGroupIngressのuser、IP、時刻）。Configは「変更前後で設定がどう変わったか、準拠しているか」に答え、CloudTrailのeventへのリンクも示せます。問いが「who」を強調していればCloudTrail、「what changed / compliant」を強調していればConfigです。

制約キーワードと対処法

  • most cost-effective、lowest cost: まず要件を満たすことが前提で、そのうえで安いもの。Spot、S3 IA/Glacier、Reserved、right-size、Gateway endpoint、HAが不要ならsingle AZ。
  • highly available、fault tolerant、minimal downtime: Multi-AZ、ASG、複数のNAT、Route 53 failover。instance 1台やAZ 1つの解決策は選びません。
  • improve performance、reduce latency: cache（CloudFront、ElastiCache、DAX）、read replica、Global Accelerator、適切なstorageの種類（io2、FSx Lustre）。
  • most secure: least privilege、userではなくrole、KMSによる暗号化、private subnet + endpoint、公開しない。
  • without code changes、existing application: インフラ側の解決策（RDS Proxy、DAX、Storage Gateway、Amazon MQ）。「appを修正して...」は選びません。

  6. AWS accountを最後に片付ける: 残ったresourceを削除し、Budget（1 USDと10 USD）とMFA付きのIAM admin userは残します。今後使わないならaccountを閉じることもできます（Account → Close account）が、残っているFree Tierのcreditは失われます。

タスク4. 試験前にAWSアカウントを片付ける

目標: 試験後、accountに時間課金されるresourceが残っておらず、Budget、IAM admin user、いくつかの無料のものだけが残っている状態にします。5日目に行い、6日目のBillsで0になったことを確認します。

  1. まず全体像を見ます: Billing and Cost Management → Bills（今月どのサービスに料金が出ているか）とCost Explorer（直近7日で絞り込み、Serviceでgroup by、次にRegionでgroup by）。まだ表示されるサービスにはresourceが残っています。Business supportがあればTrusted Advisor → Cost Optimizationも確認します（idle load balancer、unassociated EIP、underutilized EBS）。
